# Gemini를 이용한 Playwright 테스트 자동화 워크플로우

이 문서는 AI 에이전트 Gemini가 Playwright 테스트를 자동으로 실행하고, 에러를 분석 및 수정하는 워크플로우에 대해 설명합니다.

## 목표

사용자의 개입을 최소화하고, 테스트 실행부터 버그 수정까지의 과정을 자동화하여 개발 생산성을 향상시키는 것을 목표로 합니다.

## 전제 조건

-   사용자의 로컬 컴퓨터에 **Node.js** 및 **npm**이 설치되어 있어야 합니다.

## 자동화 워크플로우

사용자가 "테스트 실행하고 문제 해결해 줘"와 같이 요청하면, Gemini는 아래의 두 단계를 순차적으로 또는 반복적으로 수행합니다.

### 1단계: 환경 구성 (최초 1회)

Gemini는 테스트 실행에 필요한 환경이 구성되어 있는지 확인하고, 필요시 아래의 명령어를 실행하여 환경을 구성합니다. 이 단계의 모든 명령어는 사용자의 **승인**을 받은 후에만 실행됩니다.

1.  **`npm init -y`**: `package.json` 파일이 없을 경우, 기본 파일을 생성합니다.
2.  **`npm install --save-dev @playwright/test`**: Playwright 라이브러리를 프로젝트에 설치합니다.
3.  **`npx playwright install`**: 테스트에 필요한 브라우저(Chromium 등)를 로컬 환경에 설치합니다.

### 2단계: 실행-분석-수정 사이클

환경 구성이 완료되면, Gemini는 모든 테스트가 통과할 때까지 다음의 사이클을 반복합니다.

#### 1. 실행 (Run)

-   `npx playwright test` 명령을 실행하여 E2E 테스트를 시작합니다.

#### 2. 분석 (Analyze)

-   테스트 실행 결과를 실시간으로 읽어들입니다.
-   **(성공 시)**: 모든 테스트가 통과했음을 사용자에게 알리고 작업을 종료합니다.
-   **(실패 시)**: `stdout`과 `stderr`에 출력된 에러 메시지를 정밀하게 분석합니다. 에러의 종류(예: `TimeoutError`, `strict mode violation`), 에러가 발생한 파일명과 코드 라인, 그리고 에러의 상세 내용을 파악합니다.

#### 3. 수정 (Fix)

-   분석된 에러 원인을 바탕으로 해결 전략을 수립합니다.
-   `read_file` 툴을 사용하여 문제의 소스 코드를 읽어옵니다.
-   `replace` 툴을 사용하여 문제의 원인이 되는 코드를 수정합니다. (예: 잘못된 `locator` 수정, 비동기 대기 시간 추가, 로직 오류 수정 등)

#### 4. 반복 (Repeat)

-   코드 수정이 완료되면, 다시 **1. 실행** 단계로 돌아가 테스트를 재실행합니다.
-   이 사이클은 더 이상 수정할 에러가 없거나, 모든 테스트가 성공할 때까지 계속됩니다.

## 사용자의 역할

-   **최초 요청**: "테스트 실행해 줘" 와 같이 자동화 워크플로우를 시작하도록 요청합니다.
-   **명령어 승인**: Gemini가 환경 구성이나 테스트 실행을 위해 요청하는 셸 명령어(`run_shell_command`)의 내용을 확인하고 승인(Approve)합니다.

이 워크플로우를 통해 사용자는 테스트 실행과 디버깅의 반복적인 과정에서 벗어나 더 중요한 작업에 집중할 수 있습니다.
